# devlog · 模块开发记录（R12）

> 每个功能模块完成时必须**当回合**归档一份开发记录，否则该模块不算完成。
> 目标：新成员（人或 AI）只读 docs/ + 本目录即可无痛接手。

## 模板

```markdown
# 开发记录：<模块名> — <功能/阶段>

- 日期 / 作者 / 涉及模块 / 关联需求编号（R1-R12）/ 关联 Issue

## 1. 目标与范围
（做什么、明确不做什么）

## 2. 设计要点
（关键决策 + 为什么，含备选方案否决理由）

## 3. 接口契约
（新增/变更的类、方法签名、数据模型，含 SQL DDL；必须与 docs/03-contracts.md 同步）

## 4. 关键实现
（核心代码片段 + 可复现命令：构建/测试）

## 5. 测试与验证
（如何验证、边界用例、已知问题）

## 6. 接手指引
（下一步做什么、踩坑点、待办）
```

## 命名规则

- `M-<三位序号>-<模块>-<功能>.md`，如 `M-000-m0-scaffold.md`、`M-001-notes-crud.md`

## 归档规则

1. 功能完成当回合提交 devlog，随 PR 一起合并；
2. 接口变更必须先写 ADR（docs/adl/）再改代码；
3. 提交信息引用：`feat(notes): 说明 #R7 docs:M-002`；
4. 数据表变更同步 docs/04-database.md；接口变更同步 docs/03-contracts.md。
